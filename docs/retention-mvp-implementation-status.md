# وضعیت اجرایی MVP نگهداشت MarginLift

تاریخ بازبینی: ۱۴۰۵/۰۵/۱۹

## آنچه اکنون آماده است

- ورود فایل تراکنش و پیش‌نمایش قرارداد داده پیش از ثبت.
- نگاشت ستون‌ها برای فروشگاه اینترنتی، سوپراپ و سرویس اشتراکی.
- ردکردن شناسه‌های مستقیم شخصی و اعلام خطاهای قابل اصلاح.
- ساخت dataset نقطه‌درزمان، baseline بازگشت خرید و ممیزی leakage.
- Model Card با نسخه داده، تاریخ برش، سطح شواهد و محدودیت استفاده.
- صف تصمیم نگهداشت با اقدام پیشنهادی، دلیل تصمیم و مجوز مشوق.
- خروجی اختصاصی CRM و گزارش نقش‌محور برای مدیرعامل، CRM، مالی و داده.
- Shadow Mode بدون تماس با مشتری، با ظرفیت چرخه، exclusion و lineage کامل.
- Experiment Brief با نرخ پایه، MDE، پنجره نتیجه، سهم کنترل و حجم نمونه.
- سه سناریوی مصنوعی قابل بازنشانی؛ بازنشانی هیچ داده واقعی را حذف نمی‌کند.

## مرز ادعای فعلی

این نسخه یک ابزار تصمیم‌سازی و آماده‌سازی پایلوت است. خروجی‌های داده مصنوعی یا
تحلیل تاریخی، اثبات کاهش ریزش یا افزایش سود نیستند. اقدام زنده و ادعای اثر علّی
فقط پس از تأیید طرح آزمایش، اجرای holdout و بسته‌شدن پنجره outcome مجاز است.

## گیت‌های باقی‌مانده برای مشتری واقعی

1. دریافت نمونه ناشناس داده و تأیید قرارداد ستون‌ها توسط مالک داده.
2. توافق مکتوب بر تعریف ریزش، eligible population و واحد تخصیص.
3. اجرای حداقل دو چرخه Shadow Mode بدون خطای داده یا هم‌پوشانی مخاطب.
4. تأیید ظرفیت CRM، exclusionها، متن/کانال و مالک پاسخ‌گو.
5. تصویب Experiment Brief شامل حجم نمونه، stopping rule و guardrailها.
6. اجرای live holdout و گزارش Intention-To-Treat پس از بسته‌شدن outcome window.

## Definition of Done پایلوت

پایلوت فقط زمانی موفق محسوب می‌شود که سود افزایشی به‌ازای مشتری واجد شرایط
مثبت باشد، interval عدم‌قطعیت گزارش شود، guardrailها سالم بمانند و نتیجه با
lineage قابل بازتولید باشد. نرخ ریزش پیش‌بینی‌شده به‌تنهایی معیار موفقیت نیست.
