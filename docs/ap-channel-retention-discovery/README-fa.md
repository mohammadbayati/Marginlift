# بسته جلسه نخست MarginLift با تیم آپ

## هدف بسته

این بسته برای اعتبارسنجی مسئله «کاهش ریزش از کانال خرید بسته اینترنت در آپ» آماده شده است. جلسه نخست برای فروش دمو نیست؛ باید نشان دهد مسئله واقعی، قابل‌اندازه‌گیری، قابل‌اجرا و دارای مالک و بودجه است یا نه.

## ترتیب استفاده

1. پیام `01-outreach-message-fa.txt` برای هماهنگی جلسه ارسال شود.
2. پیش از جلسه، `02-meeting-brief-fa.md` مرور شود.
3. جلسه طبق `03-discovery-interview-fa.md` پیش برود؛ معرفی MarginLift فقط پس از بخش کشف انجام شود.
4. در صورت وجود شواهد کافی، `04-data-request-fa.md` برای مسئول Data/BI فرستاده شود.
5. بلافاصله پس از جلسه، `05-session-scorecard.csv` تکمیل شود.
6. فقط اگر امتیاز جلسه حداقل ۷ از ۱۰ بود، `06-channel-retention-diagnostic-proposal-fa.md` ارائه شود.
7. `07-one-pager-fa.md` برای هم‌راستاکردن CRM، Data و صاحب بودجه استفاده شود؛ نه به‌عنوان ادعای نتیجه قطعی.

## اجرای preflight پس از دریافت نمونه

فایل دریافت‌شده را کنار پروژه قرار دهید و اجرا کنید:

```bash
npm run retention:audit -- ap-package-transactions.csv --json
```

اگر فایل مداخله نیز ارائه شد:

```bash
npm run retention:audit -- ap-package-transactions.csv \
  --interventions ap-package-interventions.csv --json
```

قالب‌های مصنوعی `synthetic-package-transactions.csv` و `synthetic-package-interventions.csv` فقط ساختار مورد انتظار را نشان می‌دهند.

## تعریف مسئله مورد توافق

MarginLift باید احتمال خریدنکردن مجدد بسته اینترنت در کانال آپ را پیش‌بینی کند، کاربران واقعاً قابل‌بازگشت را تشخیص دهد و مشخص کند برای چه کسی، چه زمانی و تا چه سقف هزینه‌ای اقدام شود.

محدوده فعلی:

- فقط خرید بسته اینترنت؛ شارژ در تحلیل نخست ترکیب نمی‌شود.
- فقط retention در کانال آپ؛ درباره خرید از رقبا ادعایی مطرح نمی‌شود.
- تعریف پویا بر اساس موعد تمدید و الگوی خرید؛ نه یک آستانه ثابت برای همه.
- خروجی MarginLift تصمیم پیشنهادی است؛ اجرای کمپین در CRM آپ باقی می‌ماند.
- معیار نهایی سود مشارکتی افزایشی است؛ کاهش ریزش بدون کنترل هزینه مشوق کافی نیست.

## گیت تصمیم

| نتیجه جلسه | اقدام |
| --- | --- |
| شواهد واقعی + مالک + دسترسی به schema | جلسه فنی و ممیزی داده |
| درد وجود دارد ولی داده یا اختیار روشن نیست | پیگیری محدود با owner مشخص |
| علاقه شفاهی بدون رخداد، عدد یا تعهد | توقف ساخت و عدم ارسال پیشنهاد |
| داده قابل استفاده + ارزش اقتصادی | پیشنهاد Diagnostic پولی |
