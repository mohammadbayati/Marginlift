# Brief جلسه کشف Channel Retention

## مشخصات

| مورد | مقدار |
| --- | --- |
| شرکت | آسان پرداخت / آپ |
| حوزه نخست | خرید بسته اینترنت |
| مدت | ۴۵ دقیقه |
| مخاطب نخست | مدیر ارشد تلکام |
| افراد مطلوب بعدی | CRM/Growth، Data/BI و صاحب بودجه |
| نوع جلسه | Problem discovery، نه دمو و فروش |

## هدف تصمیمی

در پایان جلسه باید یکی از این سه تصمیم گرفته شود:

- `Proceed`: رزرو جلسه فنی و دریافت schema یا ۱۰۰ ردیف ناشناس.
- `Investigate`: درد محتمل است، اما owner یا داده باید روشن شود.
- `Stop`: مسئله مهم، قابل‌اندازه‌گیری یا قابل‌اجرا نیست.

## فرضیه‌ای که باید ابطال‌پذیر بماند

آپ گروه معناداری از خریداران قبلی بسته اینترنت دارد که خرید خود را در چرخه مورد انتظار تکرار نمی‌کنند؛ policy فعلی نمی‌تواند کاربران قابل‌بازگشت را از کاربران با خرید طبیعی یا غیرقابل‌بازگشت جدا کند و این موضوع به ازدست‌رفتن سود یا مصرف ناکارآمد مشوق منجر می‌شود.

## چیزی که نباید از پیش فرض شود

- عدم خرید در آپ به معنی خرید از رقیب نیست.
- افزایش conversion به معنی افزایش سود نیست.
- کاربر پرریسک الزاماً قابل‌بازگشت نیست.
- تخفیف بیشتر الزاماً retention بیشتری نمی‌سازد.
- داده خرید به‌تنهایی برای ادعای causal کافی نیست.

## خروجی مطلوب جلسه

1. شرح یک رخداد واقعی و اخیر از افت خرید مجدد یا کمپین بازگشت.
2. روش فعلی شناسایی و هدف‌گیری کاربران.
3. metric و هزینه‌ای که مدیریت واقعاً دنبال می‌کند.
4. نام ownerهای CRM، Data و بودجه.
5. پاسخ روشن درباره امکان holdout.
6. تعهد مشخص برای جلسه فنی یا داده ناشناس.

## آمادگی پیش از جلسه

- دمو باز باشد ولی تا پایان کشف نمایش داده نشود.
- ادعای درصد کاهش ریزش یا صرفه‌جویی آماده نشود.
- درباره قیمت فقط ساختار فازها توضیح داده شود؛ مبلغ پس از Data Readiness تعیین می‌شود.
- پاسخ امنیتی کوتاه آماده باشد: PII مستقیم دریافت نمی‌شود و شروع با schema و نمونه ناشناس است.
