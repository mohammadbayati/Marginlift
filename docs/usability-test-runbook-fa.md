# Runbook اجرای سه تست واقعی MarginLift

## ۱. انتخاب افراد

- P01: مدیرعامل، CMO، CFO یا مدیر کسب‌وکار که درباره بودجه تصمیم می‌گیرد.
- P02: مدیر یا کارشناس CRM، Growth یا Retention که کمپین را اجرا می‌کند.
- P03: مدیر داده، تحلیل‌گر ارشد یا مدیر مالی که کیفیت شواهد را می‌سنجد.
- یکی از این سه نفر باید جلسه را واقعاً با Narrator یا NVDA انجام دهد.

## ۲. دعوت

متن پیشنهادی واتساپ:

«سلام. برای ارزیابی یک محصول تصمیم‌یار نگهداشت مشتری، به ۲۵ دقیقه مشاهده استفاده واقعی نیاز دارم. قرار نیست توانایی شما سنجیده شود؛ می‌خواهیم ببینیم محصول بدون توضیح چقدر قابل‌فهم است. یک حساب فقط‌خواندنی و سناریوی نمونه در اختیارتان می‌گذارم. اگر موافق باشید، صفحه و صدای جلسه فقط برای ثبت ایرادهای محصول ضبط می‌شود و هیچ داده سازمانی لازم نیست.»

## ۳. ساخت حساب

برای هر نفر یک حساب viewer جدا با انقضای هفت‌روزه بسازید:

```bash
npm run demo-user -- --organization="ارزیابی MarginLift" --email=person@example.com --name="ارزیاب P01" --days=7
```

رمز خروجی فقط برای همان فرد ارسال شود و در scorecard یا Git ثبت نشود.

## ۴. اجرای جلسه

1. ضبط فقط بعد از رضایت شروع شود.
2. لینک `https://marginlift.ir/login` و اطلاعات ورود ارسال شود.
3. فایل `usability-session-console-fa.html` را در مرورگر مجری باز کنید.
4. متن شروع موجود در `usability-test-protocol-fa.md` بدون توضیح اضافه خوانده شود.
5. زمان‌سنج جلسه و زمان‌سنج هر کار را از داخل کنسول اجرا کنید.
6. پنج کار به همان ترتیب ارائه و رفتار، پیامد و شدت هر یافته همان لحظه ثبت شود.
7. برای جلسه screen reader، `screen-reader-test-protocol-fa.md` اجرا شود.

کنسول نام، ایمیل یا داده سازمانی نمی‌گیرد و اطلاعات را فقط در Local Storage همان مرورگر نگه می‌دارد. تا پایان هر سه جلسه از همان مرورگر و پروفایل استفاده کنید.

## ۵. ثبت و تصمیم

- برای هر نفر یک نسخه از `usability-test-session-template-fa.md` فقط در صورت نیاز به یادداشت پشتیبان تکمیل شود.
- پس از سه جلسه، دکمه «دریافت CSV استاندارد» در کنسول زده و فایل خروجی جایگزین `usability-test-scorecard.csv` شود.
- هر مشاهده باید رفتار واقعی، پیامد و Severity داشته باشد.
- فایل ضبط یا یادداشت محرمانه در GitHub قرار نگیرد؛ فقط یک مرجع محلی ناشناس در CSV ثبت شود.
- ارزیابی نهایی اجرا شود:

```bash
npm run usability:evaluate
```

## ۶. اصلاح و بازآزمایی

- Severity 1: ارائه متوقف و همان روز اصلاح شود.
- Severity 2: پیش از جلسه مشتری بعدی اصلاح شود.
- Severity 3: در چرخه جاری محصول اصلاح شود.
- Severity 4: فقط در backlog ثبت شود.
- اصلاح Severity 1 و 2 با همان کار و یک شرکت‌کننده هدف دوباره آزمایش شود.
- Goal فقط با خروجی `pass` ارزیاب و مدرک سه جلسه قابل تکمیل است.
