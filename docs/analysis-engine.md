# موتور تحلیل MarginLift

## هدف مرحله ۲

موتور تحلیل باید فقط KPI نسازد. خروجی باید برای مدیر رشد، مدیر مالی و مشتری پایلوت قابل دفاع باشد:

- داده معتبر است یا نه؟
- uplift نسبت به گروه کنترل چقدر است؟
- پیشنهاد هر سگمنت چه سود افزایشی دارد؟
- درآمد فعلی تا چه حد محافظت می‌شود؟
- کدام تصمیم باید با احتیاط اجرا شود؟

## ورودی فعلی

CSV aggregate با این ستون‌ها:

- `segment_fa`
- `campaign_group`
- `users`
- `conversion_rate`
- `incentive_cost_per_user_toman`
- `estimated_revenue_toman`
- `incremental_lift_points` اختیاری
- `recommended_action_fa` اختیاری

نرخ تبدیل می‌تواند به‌شکل `0.084` یا `8.4` وارد شود. موتور مقدار دوم را درصد فرض می‌کند.

## خروجی‌های جدید

### ۱. Data quality

موتور بررسی می‌کند:

- هر سگمنت گروه کنترل دارد.
- نرخ تبدیل بین صفر و یک است.
- تعداد کاربران مثبت است.
- هزینه و درآمد منفی نیستند.
- حجم کل کمپین برای تصمیم مالی کافی است.

### ۲. Uplift evidence

برای هر treatment نسبت به control محاسبه می‌شود:

- نرخ تبدیل وزنی
- uplift point
- بازه اطمینان تقریبی ۹۵٪
- هزینه متوسط هر کاربر

### ۳. Segment decision

برای هر سگمنت، موتور candidateها را مقایسه می‌کند:

- بدون پیشنهاد
- فقط پوش
- تخفیف کوچک
- مشوق قوی

تصمیم براساس projected margin، سود افزایشی، هزینه مشوق و ریسک آماری انتخاب می‌شود.

### ۴. Guardrails

قبل از اجرای پیشنهاد، این گاردریل‌ها ساخته می‌شوند:

- کیفیت داده
- درآمد محافظت‌شده
- مثبت بودن سود افزایشی مشوق پولی
- بهبود حاشیه سود

## محدودیت فعلی

این نسخه هنوز مدل causal پیشرفته یا uplift model کاربرمحور نیست. فعلاً aggregate decision engine است و برای پایلوت تاریخی مناسب است. مرحله بعدی می‌تواند از داده row-level کاربر، ویژگی‌های رفتاری، propensity/uplift model و backtesting زمانی استفاده کند.
