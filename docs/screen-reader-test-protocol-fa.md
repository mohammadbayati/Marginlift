# پروتکل تست واقعی Screen Reader برای MarginLift

## ابزار و شرکت‌کننده

- روی ویندوز از Narrator با `Win + Ctrl + Enter` یا از NVDA استفاده شود.
- شرکت‌کننده باید صفحه را بدون اتکا به تصویر و فقط با خروجی صوتی و کیبورد طی کند.
- نام screen reader، نسخه، مرورگر و زبان صدا در فرم جلسه ثبت شود.
- مجری نباید نام کنترل یا جای آن را به شرکت‌کننده بگوید.

## سناریوی آزمون

1. صفحه ورود باز شود. شرکت‌کننده باید عنوان صفحه و landmark اصلی را اعلام کند.
2. با اولین Tab، «رفتن به محتوای اصلی» شنیده و فعال شود.
3. ایمیل، رمز و دکمه ورود فقط از روی label صوتی پیدا شوند.
4. پس از ورود، heading اصلی و تصمیم پیشنهادی امروز پیدا شود.
5. شرکت‌کننده نوع شواهد، سطح اعتماد و مهم‌ترین عدد مالی را از روی خروجی صوتی بیان کند.
6. لینک صف تصمیم و دکمه دریافت گزارش پیدا و فعال شوند.
7. در گزارش، عنوان، تصمیم، محدودیت و اقدام بعدی به ترتیب منطقی خوانده شوند.
8. یک پیام وضعیت، مانند خطای ورود یا نتیجه انتخاب فایل، پس از تغییر announce شود.

## معیار قبولی

- عنوان، main landmark، heading اصلی و Skip Link درست announce شوند.
- هیچ کنترل تعاملی با عبارت «بدون نام»، «blank» یا فقط نماد خوانده نشود.
- ترتیب خواندن، تصمیم را پیش از جزئیات فنی و اقدام را پس از دلیل ارائه کند.
- کارهای ۱ تا ۷ بدون کمک انجام شوند.
- حداقل یک پیام پویا از `role=status` یا live region شنیده شود.
- هیچ خطای Severity 1 یا 2 حل‌نشده باقی نماند.

نتیجه در ستون‌های `screen_reader_used` و `screen_reader_pass` scorecard ثبت می‌شود. عبور AX Tree خودکار جای این آزمون انسانی را نمی‌گیرد.
