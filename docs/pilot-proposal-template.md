# پیشنهاد پایلوت MarginLift

## پیشنهاد

MarginLift یک پایلوت ۲ تا ۶ هفته‌ای برای کاهش هدررفت مشوق اجرا می‌کند. شروع پایلوت با داده تاریخی و aggregate است و در صورت تأیید مشتری، به live holdout محدود تبدیل می‌شود.

## خروجی‌ها

| خروجی | توضیح |
| --- | --- |
| گزارش هدررفت مشوق | نشان می‌دهد کدام بخش از هزینه احتمالا فروش incremental نساخته است |
| سیاست کمپین بعدی | برای هر سگمنت: بدون پیشنهاد، فقط پیام، تخفیف کوچک یا مشوق قوی |
| طراحی holdout | تخصیص گروه‌ها، sample size، metric و stopping rule |
| گزارش CFO-ready | صرفه‌جویی، revenue preserved، ریسک و محدودیت داده |
| جلسه readout | مرور خروجی با رشد، مالی و داده |

## دامنه زمانی

| هفته | کار |
| --- | --- |
| هفته ۱ | دریافت داده، پاکسازی، بررسی کیفیت، تحلیل تاریخی |
| هفته ۲ | گزارش diagnostic، policy پیشنهادی، تصمیم go/no-go برای live holdout |
| هفته ۳ تا ۶ | اجرای holdout محدود، monitoring گاردریل‌ها، readout نهایی |

## تعهدات مشتری

- معرفی مالک رشد/CRM و مالک داده.
- ارائه CSV aggregate یا anonymized.
- توضیح حاشیه سود یا حداقل proxy مالی.
- اجازه اجرای کنترل‌گروه محدود برای live holdout.
- جلسه تصمیم‌گیری حداکثر ۷ روز بعد از readout.

## معیار موفقیت

- حداقل ۱۰٪ کاهش هزینه مشوق یا هزینه هر incremental order.
- حفظ حداقل ۹۵٪ درآمد گزارش‌شده.
- حداقل ۳ سگمنت قابل‌اقدام.
- تصمیم روشن برای ادامه، توقف یا تست بزرگ‌تر.

## قیمت‌گذاری پیشنهادی

| پلن | قیمت | مناسب برای |
| --- | --- | --- |

| Paid Diagnostic | ۵۰ تا ۱۵۰ میلیون تومان | تحلیل تاریخی بدون live test |
| Pilot + Success Bonus | setup fee + ۵٪ تا ۱۵٪ صرفه‌جویی تاییدشده | مشتری با بودجه مشوق بالا و کنترل‌گروه |

## محدودیت‌ها

- بدون کنترل‌گروه، خروجی causal قطعی نیست.
- داده aggregate برای پایلوت کافی است، اما برای automation کامل بعدی داده granular لازم می‌شود.
- MarginLift تصمیم پیشنهادی می‌دهد؛ اجرای کمپین در سیستم مشتری انجام می‌شود.
