# Product Hardening 2

مرحله دوم hardening، دمو را از «تحلیل یک‌باره کمپین» به یک محصول قابل‌پیگیری برای پایلوت نزدیک‌تر می‌کند.

## هدف

در فروش B2B فقط خروجی تحلیل کافی نیست. مشتری باید ببیند آیا تیمش واقعا از محصول استفاده کرده، آیا به لحظه activation رسیده، و آیا خروجی قابل‌ارائه تولید شده است یا نه.

## اضافه‌شده‌ها

- endpoint داخلی `GET /api/events/summary` برای خلاصه فعالیت workspace.
- پنل «سلامت پایلوت» داخل داشبورد اصلی.
- فانل فارسی برای مسیر استفاده: بازدید داشبورد، ورود موفق، تحلیل CSV و خروجی گزارش.
- لیست فعالیت‌های اخیر با زمان فارسی و جزئیات سبک.
- تست integration برای login، ثبت event، گرفتن خلاصه eventها و export گزارش.

## ارزش برای مشتری

- مدیر رشد می‌بیند آیا تیم به تحلیل کمپین رسیده یا فقط وارد محصول شده است.
- Founder می‌تواند در پایلوت نشان دهد چندبار فایل تحلیل شده و چند گزارش خروجی گرفته شده است.
- برای مکالمه سرمایه‌گذار، محصول یک سیگنال adoption اولیه دارد، نه فقط صفحه نمایشی.

## مرزهای فعلی

- این activity log برای adoption و پایلوت است، نه audit trail امنیتی enterprise.
- داده در JSON DB محلی ذخیره می‌شود.
- نسخه production باید Postgres، retention policy، consent و role-based access داشته باشد.

## معیار پذیرش

- کاربر لاگین‌شده بتواند فانل استفاده را در داشبورد ببیند.
- بعد از export گزارش، activity log به‌روزرسانی شود.
- endpoint خلاصه فقط برای workspace لاگین‌شده داده برگرداند.
- تست سرور مسیرهای اصلی را پوشش دهد.
