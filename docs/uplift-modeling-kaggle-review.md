# بررسی منابع Kaggle برای Uplift Intelligence Lab

این یادداشت نشان می‌دهد منابع Kaggle چگونه به قابلیت‌های محصولی MarginLift تبدیل شده‌اند. هدف، کپی‌کردن نوت‌بوک‌ها نیست؛ هدف این است که منطق علمی آن‌ها به یک جریان تصمیم‌گیری قابل‌فروش برای کسب‌وکار تبدیل شود.

## منابع بررسی‌شده

- `vanguarde/study-series-uplift-modeling`: چارچوب آموزشی برای تفکیک مشتریان بر اساس واکنش به درمان.
- `latifff/uplift-modeling-for-marketing-strategic`: نگاه استراتژیک به انتخاب کمپین و مخاطب بر اساس اثر افزایشی.
- `maianhdang/demo-uplift-modeling-in-marketing`: نمونه کاربردی برای سنجش اقدام بازاریابی در برابر کنترل.
- `davinwijaya/uplift-modeling-qini-curve-with-python`: منطق Qini curve و رتبه‌بندی مخاطب بر اساس اثر افزایشی.
- `nibeditasahu/customer-retention-and-revenue-optimization-dataset`: جهت‌گیری دیتاستی برای ترکیب retention، revenue، رفتار مشتری و outcome.

## برداشت محصولی

MarginLift باید از «پیش‌بینی ریزش» عبور کند و به «تصمیم افزایشی» برسد. مدل churn فقط می‌گوید چه کسی احتمالا می‌رود؛ uplift می‌گوید روی چه کسی اقدام کردن واقعا نتیجه را عوض می‌کند.

## قابلیت‌هایی که وارد محصول شد

1. `Uplift Intelligence Lab`
   یک بخش جدید در داشبورد که اثر افزایشی، وضعیت مدل، بهترین سهم هدف‌گیری و بهترین اقدام مشاهده‌شده را نمایش می‌دهد.

2. `Reaction Types`
   مشتریان به چهار دسته محصولی تبدیل شدند:
   - `Persuadables`: قابل‌نجات با اقدام درست
   - `Sure Things`: خریدار قطعی که تخفیف نمی‌خواهد
   - `Uncertain`: نیازمند آزمایش بیشتر
   - `Lost / Sleeping`: عدم اقدام یا احتیاط

3. `Qini Curve`
   به‌جای نمایش یک امتیاز مبهم، سگمنت‌ها بر اساس سود افزایشی مرتب می‌شوند و محصول نشان می‌دهد بهترین نقطه هدف‌گیری کجاست.

4. `Treatment vs Control`
   هر اقدام با کنترل مقایسه می‌شود. اگر کنترل وجود نداشته باشد، محصول نباید ادعای causal قطعی کند.

5. `Experiment Design`
   فرضیه، KPI اصلی و guardrailها وارد خروجی تصمیم شدند تا تیم مارکتینگ بداند چطور پایلوت را اجرا کند.

## قواعد تصمیم

- احتمال خرید بالا به‌تنهایی دلیل تخفیف نیست.
- ریسک ریزش بالا به‌تنهایی دلیل خرج‌کردن نیست.
- اقدام پولی فقط وقتی پیشنهاد می‌شود که اثر افزایشی و سود مشارکتی هم‌زمان قابل‌دفاع باشند.
- `No Action` یک تصمیم معتبر است، نه نبود تصمیم.
- تا قبل از ثبت exposure و outcome در سطح مشتری، خروجی فردی نباید به‌عنوان مدل production معرفی شود.

## مسیر بعدی

نسخه فعلی از داده سگمنتی استفاده می‌کند. برای نسخه محصول واقعی باید قرارداد داده‌ی فردی اضافه شود:

| فیلد | هدف |
| --- | --- |
| `customer_id` | واحد تصمیم |
| `observation_start` / `observation_end` | پنجره مشاهده |
| `treatment` | اقدام انجام‌شده |
| `exposed_at` | زمان تماس یا نمایش پیشنهاد |
| `outcome_window_end` | پایان سنجش نتیجه |
| `converted` | خرید یا بازگشت |
| `revenue` | درآمد |
| `gross_margin` | حاشیه سود |
| `incentive_cost` | هزینه مشوق |
| `channel_cost` | هزینه کانال |

این قرارداد، پایه‌ی مدل‌های T-Learner، X-Learner، Uplift Tree و Causal Forest در نسخه بعدی است.
